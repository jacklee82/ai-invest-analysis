## 1. 데이터 현황 분석

### 1.1 보유 데이터 파일

### 1.2 데이터 구조

#### 1.2.1 유통 로데이터 (B파일) - ✅ 주요 데이터 소스

**컬럼 구조**:
```
정산기간 | 매출년도 | 매출월 | 앨범코드 | 발매일자 | 발매년도 | 투자년도 | 구분 | 앨범명 | 아티스트 | 권리사명 | 인접권료 | 유통수수료
```

**매핑 가능한 필드**:
- `매출년도 + 매출월` → `yyyymm` (YYYY-MM)
- `인접권료 + 유통수수료` → `revenue_amount` (총 매출액)
- `인접권료` → `cost_amount` (원가)
- `유통수수료` → **이익** (회사가 받는 수익)
- `구분` → `business_type` (일반/선급투자)
- `앨범명` 또는 `아티스트` → `project_name` (매칭 필요)

**비즈니스 로직**:
- 총 매출 = 인접권료 + 유통수수료
- 원가 = 인접권료 (권리사에게 지급)
- **이익 = 유통수수료** (회사 수익)

**제약사항**:
- ❌ `recoup_amount` (회수금) 데이터 없음
- ⚠️ 프로젝트명 매칭 규칙 수립 필요

#### 1.2.2 플랫폼 차트분석 - ⚠️ 변환 필요

**컬럼 구조**:
```
일자 | 년도 | 곡수 | 순위 | 곡코드 | 곡명 | 아티스트명 | 앨범명 | 발매일 | 앨범대장르 | 유통사 | 기획사
```

**매핑 가능한 필드**:
- `일자` → `week_date` (주 시작일로 변환 필요)
- `순위` → `chart_rank` (1~100)
- `곡명` 또는 `아티스트명` → `project_name` (매칭)
- `앨범대장르` → `chart_type` (가요/OST 등)

**제약사항**:
- ⚠️ 일자 단위 → 주 단위 변환 로직 필요
- ⚠️ 프로젝트명 매칭 규칙 필요
- ⚠️ 중복 데이터 처리 필요

## 4. 위젯별 상세 설계

### 4.1 요약 카드 (3개)

#### 4.1.1 총 매출
- **값**: `SUM(cashflow_monthly.revenue_amount)`
- **표시**: 원 단위 (억원 단위 자동 변환)
- **필터**: 기간, 사업타입, 권리사
- **스타일**: 파란색 계열

#### 4.1.2 총 이익
- **값**: `SUM(revenue_amount - cost_amount)`
- **표시**: 원 단위
- **필터**: 기간, 사업타입, 권리사
- **스타일**: 녹색 계열

#### 4.1.3 평균 이익률
- **값**: `(총 이익 / 총 매출) × 100`
- **표시**: % (소수점 1자리)
- **필터**: 기간, 사업타입, 권리사
- **스타일**: 보라색 계열

---

### 4.2 월별 매출 추세

#### 데이터 구조
```typescript
{
  yyyymm: "2025-01",
  revenue: number,    // 총 매출액
  cost: number,      // 총 원가
  profit: number,    // 이익
  margin: number     // 이익률 (%)
}
```

#### 집계 로직
```sql
SELECT 
  yyyymm,
  SUM(revenue_amount) AS revenue,  -- 총 매출액 (인접권료 + 유통수수료)
  SUM(cost_amount) AS cost,        -- 원가 (인접권료)
  SUM(revenue_amount) - SUM(cost_amount) AS profit,  -- 이익 (유통수수료)
  (SUM(revenue_amount) - SUM(cost_amount)) / NULLIF(SUM(revenue_amount), 0) * 100 AS margin  -- 이익률
FROM cashflow_monthly
WHERE yyyymm >= '2022-01' AND yyyymm <= '2025-07'
GROUP BY yyyymm
ORDER BY yyyymm;
```

**비즈니스 로직**:
- `revenue_amount` = 인접권료 + 유통수수료 (총 매출액)
- `cost_amount` = 인접권료 (원가, 권리사에게 지급)
- `profit` = 유통수수료 (이익, 회사 수익)
- `margin` = (유통수수료 / 총 매출액) × 100

#### 시각화
- X축: 년월 (YYYY-MM)
- Y축(왼쪽): 매출액 (면적 차트)
- Y축(오른쪽): 이익률 (선 그래프)
- 색상: 매출(청록색), 이익률(보라색)

## 5. 데이터 변환 전략

### 5.1 B파일 변환 (유통 로데이터 → cashflow_monthly)

#### 변환 스크립트 구조
```typescript
interface RawRow {
  정산기간: string;
  매출년도: string;
  매출월: string;
  앨범코드: string;
  구분: string;
  앨범명: string;
  아티스트: string;
  권리사명: string;
  인접권료: string;
  유통수수료: string;
}

function convertToCashflowMonthly(row: RawRow): CashflowMonthlyRow {
  // 1. yyyymm 변환
  const yyyymm = convertYearMonth(row.매출년도, row.매출월);
  
  // 2. 매출액 계산 (총 매출 = 인접권료 + 유통수수료)
  const revenueAmount = parseInt(row.인접권료.replace(/,/g, '')) + 
                        parseInt(row.유통수수료.replace(/,/g, ''));
  
  // 3. 원가 계산 (인접권료 = 권리사에게 지급하는 금액)
  const costAmount = parseInt(row.인접권료.replace(/,/g, ''));
  
  // 4. 이익 = 유통수수료 (회사가 받는 수익)
  // profit = revenueAmount - costAmount = 유통수수료
  
  // 4. 프로젝트명 결정 (앨범명 또는 아티스트)
  const projectName = row.앨범명 || row.아티스트;
  
  // 5. 사업타입 결정
  let businessType = row.구분 === '선급투자' ? '선급투자' : '일반투자';
  if (row.앨범명.includes('OST')) {
    businessType = 'OST';
  }
  
  return {
    projectId: findProjectByName(projectName), // 매칭 필요
    yyyymm,
    revenueAmount,  // 총 매출액 (인접권료 + 유통수수료)
    costAmount,    // 원가 (인접권료)
    recoupAmount: 0, // 데이터 없음
    // 이익 = revenueAmount - costAmount = 유통수수료
  };
}
```

#### 프로젝트명 매칭 규칙
1. **앨범명 우선**: `앨범명`이 있으면 `앨범명` 사용
2. **아티스트 대체**: `앨범명`이 없으면 `아티스트` 사용
3. **매칭 실패 시**: 새 프로젝트 생성 또는 경고 로그

### 5.2 차트 데이터 변환 (플랫폼 차트분석 → chart_entry)

#### 변환 스크립트 구조
```typescript
interface RawChartRow {
  일자: string;        // "2024-01-01"
  순위: string;        // "1"
  곡명: string;
  아티스트명: string;
  앨범명: string;
  앨범대장르: string;  // "가요", "OST" 등
}

function convertToChartEntry(row: RawChartRow): ChartEntryRow {
  // 1. 주 시작일 계산 (월요일)
  const weekStart = getWeekStart(row.일자);
  
  // 2. 순위 확인 (100위권만)
  const rank = parseInt(row.순위);
  if (rank > 100) return null;
  
  // 3. 프로젝트명 결정
  const projectName = row.곡명 || row.아티스트명;
  
  return {
    projectId: findProjectByName(projectName),
    chartRank: rank,
    weekDate: weekStart,
    chartType: row.앨범대장르 || '가요',
  };
}

function getWeekStart(dateStr: string): string {
  const date = new Date(dateStr);
  const day = date.getDay();
  const diff = date.getDate() - day + (day === 0 ? -6 : 1); // 월요일로 조정
  const monday = new Date(date.setDate(diff));
  return monday.toISOString().split('T')[0];
}
```

## 8. 데이터 품질 이슈 및 해결

### 8.1 프로젝트명 매칭 불확실성
**문제**: `앨범명` 또는 `아티스트명`으로 프로젝트를 찾아야 함
**해결**: 
- 매칭 규칙 수립 (앨범명 우선, 아티스트 대체)
- 매칭 실패 시 새 프로젝트 자동 생성
- 매칭 리포트 생성

### 8.2 회수금 데이터 없음
**문제**: `recoup_amount` 필드에 데이터 없음
**해결**: 
- `recoup_amount = 0`으로 설정
- 회수금 관련 위젯은 제외

### 8.3 원가 및 이익 계산
**비즈니스 로직**: 
- 총 매출액 = 인접권료 + 유통수수료
- 원가 = 인접권료 (권리사에게 지급)
- **이익 = 유통수수료** (회사가 받는 수익)
- 이익률 = (유통수수료 / 총 매출액) × 100

### 8.4 차트 데이터 변환 복잡성
**문제**: 일자 단위 → 주 단위 변환 필요
**해결**: 
- `getWeekStart()` 함수 구현
- 중복 제거 로직 추가
