## 2. 데이터 구조 분석

### 2.1 유통 로데이터 (B파일) - ✅ 대시보드 구현 가능

**컬럼 구조**:
```
정산기간 | 매출년도 | 매출월 | 앨범코드 | 발매일자 | 발매년도 | 투자년도 | 구분 | 앨범명 | 아티스트 | 권리사명1 | 권리사명 | 인접권료 | 유통수수료
```

**예시 데이터**:
```
202502 | 2025년 | 2월 | 44927268 | 구보 | 2022년 이전 | 2024년 | 일반 | Evergreen | PK헤만 | (주) 지티엘 라이브 | 734,052 | 110,108
```

**매핑 가능 여부**: ✅ **매핑 가능**

**매핑 로직**:
- `매출월` → `yyyymm` (YYYY-MM 형식 변환 필요)
- `인접권료 + 유통수수료` → `revenue_amount` (매출액)
- `유통수수료` → `cost_amount` (원가, 일부만)
- `구분` → `business_type` (일반/선급투자)
- `앨범명` 또는 `아티스트` → `project_name` (프로젝트 매칭 필요)

**문제점**:
1. ❌ **프로젝트명 매칭 불확실**: `앨범명` 또는 `아티스트`로 프로젝트를 찾아야 함
2. ❌ **회수금 정보 없음**: `recoup_amount` 필드에 매핑할 데이터가 없음
3. ⚠️ **원가 계산 불완전**: `유통수수료`만으로는 원가를 완전히 계산할 수 없음

**해결 방안**:
- 프로젝트명 매칭 규칙 수립 필요 (앨범명/아티스트명 기반)
- 회수금은 별도 데이터 소스 필요 또는 `project.total_recouped` 활용
- 원가는 `유통수수료`만 사용하거나 추가 계산 필요

---

### 2.2 플랫폼 차트분석 (차트 데이터) - ⚠️ 조건부 가능

**컬럼 구조**:
```
일자 | 년도 | 곡수 | 순위 | 곡코드 | 곡명 | 아티스트명 | 앨범명 | 발매일 | 발매년도 | 앨범소장르 | 앨범대장르 | 유통사 | 기획사
```

**예시 데이터**:
```
2024-01-01 | 2024년 | 1 | 1 | 104534602 | To. X | 태연 | To. X - The 5th Mini Album | 2023-11-27 | 이전 발매 | R&B/소울 | 가요 | 카카오엔터 | SM ENTERTAINMENT
```

**매핑 가능 여부**: ⚠️ **조건부 가능**

**매핑 로직**:
- `일자` → `week_date` (주 시작일로 변환 필요: 월요일)
- `순위` → `chart_rank` (1~100)
- `곡명` 또는 `아티스트명` → `project_name` (프로젝트 매칭)
- `앨범대장르` → `chart_type` (가요/OST 등)

**문제점**:
1. ❌ **일자 단위 → 주 단위 변환 필요**: `chart_entry`는 주 단위 저장
2. ❌ **프로젝트명 매칭 불확실**: 곡명/아티스트명으로 프로젝트 찾기
3. ⚠️ **중복 데이터**: 같은 곡이 여러 날짜에 중복 기록

**해결 방안**:
- 일자 → 주 변환 로직 구현 (월요일 기준)
- 프로젝트명 매칭 규칙 수립
- 중복 제거 로직 필요

---

### 2.3 유통 목록 (메타데이터) - ⚠️ 참고용

**컬럼 구조**:
```
타입 | 아티스트명 | 앨범명 | 곡명 | 투자구분 | 서비스적용일 | 권리사
```

**용도**: 프로젝트명 매칭을 위한 참고 데이터
**매핑**: 직접 매핑 불가, 참고용으로만 활용

---

### 2.4 가온차트 음반 판매 (음반 사업 참고) - ⚠️ 참고용

**컬럼 구조**:
```
년도 | 월 | 앨범명 | 앨범유형 | 플랫폼 앨범 종류 | 아티스트명 | 유형 | 음반 판매량 | 유통사
```

**용도**: 음반 사업 프로젝트의 판매량 참고
**매핑**: 직접 매핑 불가, 참고용으로만 활용

## 3. 대시보드 구현 가능성 평가

### 3.1 ✅ 구현 가능한 위젯 (데이터 변환 후)

#### 3.1.1 월별 추세
- **데이터 소스**: `유통 로데이터` → `cashflow_monthly`
- **필요 작업**:
  1. `매출월` → `yyyymm` 변환
  2. `인접권료 + 유통수수료` → `revenue_amount` 계산
  3. `유통수수료` → `cost_amount` (또는 추가 계산)
- **구현 난이도**: 중

#### 3.1.2 사업별 성과 비교
- **데이터 소스**: `유통 로데이터` → `cashflow_monthly` + `project`
- **필요 작업**:
  1. `구분` (일반/선급투자) → `business_type` 매핑
  2. 프로젝트명 매칭
- **구현 난이도**: 중

### 3.2 ❌ 구현 불가능한 위젯 (데이터 부족)

#### 3.2.1 KPI 카드 (누적 투자금, 회수금, 회수율)
- **문제**: A파일 데이터가 없음
- **필요 데이터**: `project` 테이블 (투자금, 회수금, 계약 정보)
- **해결**: A파일 업로드 필요 또는 별도 데이터 소스

#### 3.2.2 투자→회수 워터폴
- **문제**: 투자금, 회수금 데이터 없음
- **필요 데이터**: `project` 테이블
- **해결**: A파일 업로드 필요

#### 3.2.3 Top 기획사 스캐터
- **문제**: 투자금, 회수율 데이터 없음
- **필요 데이터**: `project` 테이블
- **해결**: A파일 업로드 필요

#### 3.2.4 리스크 건수
- **문제**: 계약 정보, 투자금, 회수금 데이터 없음
- **필요 데이터**: `project` 테이블
- **해결**: A파일 업로드 필요

#### 3.2.5 계약 만기 예정
- **문제**: 계약 시작일, 계약 기간 데이터 없음
- **필요 데이터**: `project` 테이블
- **해결**: A파일 업로드 필요

## 4. 데이터 변환 전략

### 4.1 B파일 변환 (유통 로데이터 → cashflow_monthly)

#### 변환 스크립트 필요
```typescript
// 1. 파일 파싱 (탭 구분)
const rows = parseTabDelimited(file);

// 2. 데이터 변환
const cashflows = rows.map(row => ({
  projectId: findProjectByName(row.앨범명 또는 row.아티스트), // 매칭 필요
  yyyymm: convertToYYYYMM(row.매출년도, row.매출월), // "2025-02"
  revenueAmount: parseInt(row.인접권료) + parseInt(row.유통수수료),
  costAmount: parseInt(row.유통수수료), // 또는 추가 계산
  recoupAmount: 0, // 데이터 없음, 별도 소스 필요
}));
```

#### 변환 규칙
- `매출년도 + 매출월` → `yyyymm` (예: "2025년" + "2월" → "2025-02")
- `인접권료 + 유통수수료` → `revenue_amount`
- `유통수수료` → `cost_amount` (일부만, 완전한 원가 아님)
- `구분` → `business_type` 매핑:
  - "일반" → "일반투자"
  - "선급투자" → "선급투자"
  - OST, 음반은 별도 판단 필요

### 4.2 차트 데이터 변환 (플랫폼 차트분석 → chart_entry)

#### 변환 스크립트 필요
```typescript
// 1. 일자 → 주 시작일 변환
function getWeekStart(date: string): string {
  // 월요일 기준으로 변환
}

// 2. 데이터 변환
const chartEntries = rows
```

## 5. 결론 및 권장사항

### 5.1 현재 상태로 구현 가능한 대시보드

**✅ 부분 구현 가능**:
1. **월별 매출 추세** (B파일 데이터만)
   - 월별 매출액 집계
   - 월별 이익 계산 (매출 - 원가)
   - 사업타입별 필터링

2. **사업별 성과 비교** (B파일 데이터만)
   - 일반투자 vs 선급투자 매출 비교
   - 이익률 계산 (일부만)

**❌ 완전 구현 불가능**:
- KPI 카드 (투자금, 회수금, 회수율)
- 리스크 관리
- 투자→회수 워터폴
- Top 기획사 분석
- 계약 만기 관리

### 5.2 필수 선행 작업

#### 우선순위 1: A파일 데이터 준비
- **프로젝트 마스터 데이터** (투자금, 회수금, 계약 정보)
- **형식**: Excel 또는 CSV
- **필수 컬럼**: 프로젝트명, 기획사명, 계약시작일, 기본계약기간, 최초투자금, 총회수금, BM구분

#### 우선순위 2: 데이터 변환 스크립트
- **B파일 변환**: `유통 로데이터` → `cashflow_monthly`
- **차트 데이터 변환**: `플랫폼 차트분석` → `chart_entry`
- **프로젝트명 매칭 규칙** 수립

#### 우선순위 3: 데이터 검증
- 프로젝트명 매칭율 확인
- 데이터 누락 확인
- 금액 데이터 유효성 검증

### 5.3 권장 구현 순서

#### Phase 0: 데이터 준비 (필수)
1. A파일 데이터 수집/정리
2. B파일 변환 스크립트 작성 및 실행
3. 데이터 검증 및 매칭률 확인

#### Phase 1: 제한적 대시보드 (B파일만)
1. 월별 매출 추세
2. 사업별 매출 비교 (일부만)

#### Phase 2: 완전한 대시보드 (A파일 추가 후)
1. KPI 카드 전체
2. 리스크 관리
3. 투자→회수 워터폴
4. Top 기획사 분석

## 7. 결론

**현재 상태로는 완전한 대시보드 구현 불가능**

**이유**:
1. ❌ A파일 데이터 없음 (투자금, 회수금, 계약 정보)
2. ⚠️ B파일 데이터는 있으나 변환 작업 필요
3. ⚠️ 프로젝트명 매칭 규칙 수립 필요
4. ⚠️ 차트 데이터는 일자 단위 → 주 단위 변환 필요

**권장 조치**:
1. **A파일 데이터 수집** (최우선)
2. **데이터 변환 스크립트 작성**
3. **프로젝트명 매칭 규칙 수립**
4. **데이터 검증 후 단계적 구현**

**대안**: A파일 없이도 B파일만으로 제한적 대시보드 구현 가능 (월별 매출, 사업별 비교만)
